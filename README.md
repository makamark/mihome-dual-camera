# 双路摄像头监控（Dual Camera Monitoring）

把两路摄像头画面合成为一路，接入 AINICE 视觉传感器的分区有人检测，检测结果沿设备原有通道输出给米家 / Home Assistant。

一个插件解决三件事：**拉流**（米家账号授权后本地直连，或任意 RTSP 摄像头直连）、**合成**（左右并排 5:3 满幅画布）、**接入检测**（推送设备视觉管线，检测区域在设备「总览」界面绘制）。

## 功能

- **双路合成**：两路画面各取 400×480，左右并排成 800×480 画布（5:3），与设备检测模型的输入比例完全一致——全画面零盲区、零拉伸、零时延。
- **取景宽度**：每路可选 1.0×–2× 横向压缩取景——把更宽的原画面（最多 94% 覆盖）压进同一画布，视野更大（画面里的人会显瘦一点），画布与检测几何不变。
- **取流地址**：每路在面板给出局域网 RTSP 取流地址（米家路为设备上的认证 RTSP 输出），一键复制给 VLC / Home Assistant 等使用；检测走内部通道不占用该地址，外部播放与检测并存（同一时间仍只允许一个外部播放器连接）。
- **米家接入**：面板内完成账号授权（手机号 + 短信验证码），凭证由插件自持并在运行中自动续期，无需安装其他摄像头插件。
- **双目画面**：米家双目摄像头每路可选「画面 1 / 画面 2」，切换即时生效（参考 mhcamera：画面 2 即在取流源上追加 `channel=2`），取流地址的内容随所选画面变化。
- **自行接入**：每路可切换为 `rtsp://` 直连（海康 / 大华 / TP-Link 等标准 RTSP 摄像头或 NAS 流媒体），或粘贴 `xiaomi://账号:cn@IP?did=设备ID` 小米取流链接，填入地址即时生效，无需保存。
- **取景器**：面板内嵌每路完整原画，拖动蓝色取景框选择画面范围，支持靠左 / 居中 / 靠右预设，所见即所得。
- **检测区域**：在设备官方「总览」界面的合成画面上直接绘制 Zone-A..H，左半边对应第 1 路、右半边对应第 2 路。
- **可视化面板**：实时预览、每路状态与离线原因、帧率调节、深浅色跟随系统。
- **可靠运行**：首次启动自动生成默认配置，秒级就绪；单路离线自动降级置灰并在画面恢复后自动亮起；会话断流自动重连、实例崩溃自动重建。

## 安装

1. 从 [Releases](https://github.com/makamark/mihome-dual-camera/releases) 下载最新 `multicam-<版本>.plugin`，在设备 Web 控制台 **插件 → 导入** 上传（也可以 `POST /api/plugins/import` 上传原始字节流，`Content-Type: application/vnd.ainice.plugin`）。
2. 启用插件。首次启动会自动生成默认配置，一两秒内进入就绪状态。
3. 控制台打开插件面板 → **账号授权** → 输入手机号与短信验证码完成米家授权。
4. 在每路的设备下拉中选择米家摄像头；或切换「自行接入」填入 `rtsp://` 地址。
5. 在设备官方「总览」界面上，对合成画面绘制检测区域。

## 使用注意

- **一台摄像头同一时间只能被一台设备拉流。** 米家摄像头对并发视频会话会做轮换，两台设备同时拉同一台摄像头会导致画面异常，请先停用另一台设备上的拉流。米家双目摄像头同理：同一台双目摄像头一次只能取一个画面，把两路都指向同一台双目摄像头（即使画面各选一边）也会互相踢会话。
- 启用本插件后，设备的视觉检测输入即切换为合成画面；停用插件后自动恢复设备原有摄像头画面。
- 自行接入 RTSP 源的分辨率等要求见下方「自行接入 RTSP」。
- `xiaomi://` 小米链接的账号需与本插件已授权的米家账号一致（链接里的凭证部分只是账号标识，真正取流靠插件自持的授权）。
- 米家路的取流地址同一时间只允许一个外部播放器连接（厂商输出为单观看者）；插件检测经 AIV1 内部通道消费画面，不占用该地址——外部播放无需再暂停检测。
- 输出帧率按 CPU 占用选择：每秒 3 帧 CPU 最低（默认）、5 帧适中、8 帧较高。
- 合成画面会替换设备原摄像头画面参与检测；单独某一路离线不影响另一路检测。

## 自行接入 RTSP

**地址格式**：`rtsp://用户名:密码@IP[:端口]/路径`，不写端口默认 554。密码里的 `/ ? # %` 需分别写成 `%2F %3F %23 %25`，其余字符（含 `@` `:`）可原样填写。

**源要求**（当前版本）：

- **分辨率**：请选用 **848×480**，或宽度不小于 400、高度恰好 480 的子码流，两路保持同一分辨率。高度不是 480 的源会改变画布尺寸或被置灰；宽度小于 400（如 352×288）无法显示。取景器按 848 宽绘制，其他宽度下蓝框位置仅供参考。
- **编码**：H.264 / H.265 / MJPEG，8 bit 4:2:0。H.265 Main10、4:2:2 格式无法显示。
- **传输**：插件固定用 RTSP over TCP 拉流；只支持 UDP 的摄像头连不上。不支持 `rtsps://`。
- **关键帧间隔**：建议设为 3 秒以内（关掉 H.264+/智能编码），插件才会启用省电的 GOP 窗口解码；否则全帧率解码，CPU 明显更高。
- 认证失败、路径错误等具体原因目前只写进插件日志，面板显示为"无帧"；填写前请先用 VLC 确认地址能播放。

**常见品牌子码流地址**（默认值，不同型号可能有差异）：

| 来源 | 子码流示例 |
|---|---|
| 海康威视 | `rtsp://admin:密码@IP:554/Streaming/Channels/102` |
| 大华 / 乐橙 | `rtsp://admin:密码@IP:554/cam/realmonitor?channel=1&subtype=1` |
| TP-Link Tapo | `rtsp://用户名:密码@IP:554/stream2`（需先在 App 里创建「摄像头账号」） |
| 萤石 | `rtsp://admin:验证码@IP:554/h264/ch1/sub/av_stream`（需先在 App 里开启局域网 RTSP，验证码在机身标签上） |
| Reolink | `rtsp://admin:密码@IP:554/h264Preview_01_sub` |
| go2rtc / Frigate / NAS 转流 | `rtsp://IP:8554/流名称` |

**怎么获取 RTSP 地址**：

1. 查摄像头说明书或厂家 App 的"RTSP / ONVIF / 第三方平台接入"设置，很多品牌需要先手动开启。
2. 用 ONVIF Device Manager（Windows）或厂家工具搜索局域网摄像头，可直接列出各码流的 RTSP 地址。
3. 摄像头本身不提供 RTSP 时，可以先接进 NAS 上的 go2rtc、Frigate 或群晖 Surveillance Station，再把它们转出的 RTSP 地址填进来；在 go2rtc 里还可以顺便缩放到 848×480。
4. 小米摄像头大多不在局域网开放 RTSP，直接用面板里的「米家」接入即可。

## 工作原理

插件随包自带 go2rtc（启用米家源）与 FFmpeg 运行库：米家授权完成后经云端密钥交换与摄像头建立本地直连会话，拉取 848×480 HEVC 子码流，经 AIV1 内部通道（unix socket 直消费，协议参考 mhcamera）绕过 RTSP 回环；FFmpeg 软解并按取景框裁切合成 YUV420P 画布，经设备 SDK 以 bitstream 模式推送视觉管线；go2rtc 会话由守护线程自动重建（AIV1 消费端随实例代际自动重连），凭证运行中自动续期并原子持久化。

## 从源码构建

仓库提供交叉编译环境（`build-env/`）。两个第三方二进制因许可与体积原因不随仓库分发，构建前需自行放置：

- go2rtc（在其基础上启用米家源与本地 RTSP 输出的构建）→ `reference/mhcamera/bin/go2rtc`
- aarch64 FFmpeg 库（libavcodec / libavformat / libavutil）→ `thirdparty/ffmpeg-aarch64/lib`

```bash
docker build -t ainice-build build-env
docker run --rm -v "$(pwd)":/work ainice-build make -C multicam package
```

产物为 `multicam/multicam-<版本>.plugin`。
